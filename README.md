# Поиск выпускных квалификационных работ

Локальный FastAPI-бэкенд ищет карточки ВКР по описанию темы. BM25 работает
без Ollama, весов модели и GPU. По желанию подключается гибридный поиск:
BM25 + семантические векторы BGE-M3 через отдельно установленную Ollama.
Результаты — существующие карточки, а не сгенерированные ответы.

Сервер может стартовать без БД. `PUT /theses` загружает корпус в SQLite
и сразу обновляет поиск; после перезапуска корпус восстанавливается из БД.
Тип поиска выбирается в каждом запросе: `bm25` (по умолчанию) или `hybrid`.
UI в репозитории нет; доступны HTTP API и Swagger `/docs`.

## Быстрый старт с Docker

Нужны установленный и запущенный Docker с актуальным **Docker Compose v2**,
свободный порт **8000** и браузер. В Windows/macOS подойдёт Docker Desktop
в режиме Linux-контейнеров; в Linux — Docker Engine с Compose plugin.
Python, `.env`, Ollama, GPU и веса моделей не нужны.
Первичная сборка скачивает базовый образ и Python-зависимости; оформление Swagger
загружается из CDN, поэтому для него также нужен интернет.

Скачайте проект, откройте терминал в каталоге с этим README и выполните **одну команду**.

macOS/Linux (bash):

```bash
bash scripts/start.sh
```

Windows (PowerShell):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

`Bypass` действует только для этого процесса и не меняет системную политику.
Скрипт собирает и запускает единственный сервис, ждёт готовности `/health`
не более **120 секунд после сборки** и открывает
[Swagger](http://localhost:8000/docs) системным браузером. Если браузер не открылся,
перейдите по ссылке вручную: API продолжает работать. При сбое запуска скрипт
показывает ошибку Compose и последние логи. Ожидание использует
[`compose up --wait --wait-timeout`](https://docs.docker.com/reference/cli/docker/compose/up/).

В Swagger откройте **POST /theses/search → Try it out → Execute**.
Готовый пример `Rasdaman` найдёт «LLM для описания спутниковых данных»;
в списке примеров есть запрос про музеи (`UTAUT2`) и запрос без совпадений.
`PUT /theses` для этого не нужен: он **полностью заменяет** корпус.

Логи остаются в терминале. **Ctrl+C** останавливает контейнер и сохраняет данные.
Повторный запуск — той же командой, в том числе после изменения исходников:
образ пересобирается, SQLite остаётся в именованном volume `proj2697_corpus`.
Демокорпус из `data/sample_theses.json` импортируется только при отсутствии БД.
Существующая, в том числе повреждённая или пустая БД, не перезаписывается.
Локальные `.env` и SQLite с компьютера не копируются в образ; контейнер использует
свою БД и явно выключенную Ollama. API опубликован только на `127.0.0.1:8000`.
Если терминал был аварийно закрыт, остановите окружение из корня проекта:
`docker compose -p proj2697 -f compose.yaml stop`.
Не удаляйте volume, если хотите сохранить импортированный корпус.

## Обычный запуск через Python: требования

Следующие разделы описывают самостоятельный запуск без Docker; после быстрого
старта выше выполнять их не нужно.

- Для воспроизведения проверенного окружения используйте **Python 3.12** с `pip`,
  `venv` и стандартным модулем `sqlite3`. Код и метаданные закреплённых зависимостей
  допускают Python 3.11; исполнение на 3.11 и более новых версиях здесь не проверено.
- Зависимости перечислены в [requirements.txt](requirements.txt), тестовые —
  в [requirements-dev.txt](requirements-dev.txt). Первичная установка требует
  доступа к индексу Python-пакетов либо заранее подготовленных совместимых wheels.
  Не все сочетания ОС, архитектуры и Python имеют готовые wheels NumPy/Pydantic.
- Нужны права чтения проекта и записи в каталог выбранной SQLite, свободный порт
  8000 и память для корпуса и поисковых структур. BM25 не требует ускорителя.
- Команды ниже рассчитаны на bash/zsh в Linux/macOS и PowerShell в Windows.
  Для HTTP-примеров нужен настоящий cURL: `curl` в bash/zsh, `curl.exe` в PowerShell.
  Проверьте `curl --version` или `curl.exe --version`; установите cURL, если его нет.
- Для hybrid дополнительно нужны совместимая с вашей ОС Ollama и локальная
  `bge-m3:latest`. Скорость, доступность ускорения и потребление памяти зависят
  от установки Ollama и оборудования. Apple Silicon или CUDA не являются условием
  работы приложения. Установленные зависимости Python не скачивают модель.

Исполнением проверен Python 3.12 на macOS arm64. Инструкции Windows/Linux
проверены анализом; это не заявление о тестировании на всех платформах.

## Установка

Перенесите исходники, файлы зависимостей и `data/` в выбранный каталог.
Не переносите `.venv`, кэши и веса как часть Python-проекта: окружение создаётся
заново на целевом компьютере. Личная `.env` и SQLite не входят в Git. Если нужен
существующий корпус, остановите API и все писатели перед копированием БД;
для независимого первого запуска используйте новый путь SQLite.

Откройте терминал **в корне проекта** — каталоге с `main.py` и этим README.
Пути с пробелами и кириллицей допустимы; аргументы путей берите в кавычки.
Все дальнейшие команды выполняются из корня, если явно не указано иное.

bash/zsh:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python --version
python -m pip install -r requirements.txt
python -m pip check
```

PowerShell (с установленным Python Launcher):

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python --version
python -m pip install -r requirements.txt
python -m pip check
```

Если Launcher отсутствует, используйте команду установленного Python 3.12
вместо `py -3.12`. Если политика PowerShell запрещает `Activate.ps1`, активация
не обязательна: во **всех** следующих командах замените `python` на
`.\.venv\Scripts\python.exe`, включая установку зависимостей. Аналогично в
bash/zsh можно использовать `./.venv/bin/python`. Не меняйте системную политику
ради активации. При открытии второго терминала повторите активацию или используйте
полный путь к интерпретатору окружения.

## Настройка

Для BM25 достаточно настроек по умолчанию, `.env` необязателен. Если нужны свои
настройки, создайте `.env` из [.env.example](.env.example). Одинаковая команда для обеих
оболочек; режим `xb` запрещает перезапись существующего файла:

```text
python -c "from pathlib import Path; Path('.env').open('xb').write(Path('.env.example').read_bytes())"
```

Если получили `FileExistsError`, файл уже есть: откройте его в редакторе
и проверьте значения, повторное копирование не нужно. Сохраняйте `.env` в UTF-8
без BOM. Для первого BM25-сценария задайте `OLLAMA_ENABLED=false` и путь к новой
БД, например `DATABASE_PATH=data/theses.sqlite3`. **Не создавайте пустой SQLite-файл:**
файл и недостающие родительские каталоги создаются при успешном импорте.
Если по выбранному пути уже есть корпус, импорт ниже полностью заменит его.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `DATABASE_PATH` | `data/theses.sqlite3` | Путь к файлу SQLite; относительный — от корня проекта, независимо от рабочего каталога |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`, `NOTSET`; регистр не важен |
| `OLLAMA_ENABLED` | `false` | `true` подключает Ollama при старте и включает вычисление векторов при HTTP-импорте; регистр не важен |
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | HTTP loopback: `127.0.0.1`, `localhost` или `[::1]`, без учётных данных, пути API, query и fragment |
| `OLLAMA_TIMEOUT_SECONDS` | `120` | Конечный положительный таймаут сетевых операций отдельного HTTP-запроса к Ollama, в секундах; не общий срок всего импорта |

Настройки читаются при старте API или запуске CLI. **Окружение процесса имеет
приоритет над `.env`**, поэтому изменение файла не отменяет ранее экспортированную
переменную. После изменения перезапустите API. `.env` всегда ищется в корне
проекта; файл из текущего рабочего каталога не подхватывается. Подстановка
`${VARIABLE}` отключена, `~` не раскрывается в домашний каталог. На Windows
в `.env` удобны прямые слеши, например `DATABASE_PATH=C:/Projects/Search/data/index.sqlite3`;
для обратных слешей используйте одинарные кавычки, чтобы `\t` и `\n` не стали
управляющими символами. Пути с пробелами можно заключать в кавычки.

Для временного переопределения значения в терминале перед запуском:

```bash
export DATABASE_PATH="data/demo.sqlite3"
export OLLAMA_ENABLED="false"
```

```powershell
$env:DATABASE_PATH = "data/demo.sqlite3"
$env:OLLAMA_ENABLED = "false"
```

Чтобы снова использовать `.env`, удалите переопределения: в bash/zsh
`unset DATABASE_PATH OLLAMA_ENABLED`, в PowerShell
`Remove-Item Env:DATABASE_PATH, Env:OLLAMA_ENABLED -ErrorAction SilentlyContinue`.
По тому же правилу задаются и удаляются остальные настройки.

`SEARCH_MODE` не является настройкой процесса и игнорируется: используйте
`search_mode` в теле поиска. Модель, размерность и устройство не настраиваются
через `.env`: модель фиксирована, устройство выбирает Ollama. `LOG_LEVEL`
управляет логами приложения; собственные логи Uvicorn — его флагом `--log-level`.

## Запуск BM25

В первом терминале из корня проекта с выбранным Python окружения:

```text
python -m uvicorn main:app --host 127.0.0.1 --port 8000 --workers 1
```

Оставьте терминал открытым; остановка — Ctrl+C. Используйте **один worker**:
поисковый снимок и блокировки принадлежат одному процессу. Несколько workers
могут отвечать по разным корпусам после импорта. `--reload` для этого сценария
не нужен. Сервер слушает только локальный интерфейс.

Во втором терминале откройте тот же корень проекта и активируйте окружение.
В bash/zsh:

```bash
curl --noproxy "*" -sS -i http://127.0.0.1:8000/health
```

В PowerShell:

```powershell
curl.exe --noproxy "*" -sS -i http://127.0.0.1:8000/health
```

Для отсутствующей БД ожидается **HTTP 503**:

```json
{"status":"not_ready","index_loaded":false,"documents_count":0,"search_mode":"bm25","embedding_model":null}
```

Это штатное ожидание импорта. `/docs`, `/openapi.json` и `PUT /theses` доступны.
Если корпус уже сохранён, health сразу вернёт 200. `/health` проверяет готовность
поискового снимка, но не выполняет inference и не проверяет живую Ollama после старта.

## Импорт и поиск на примере из репозитория

[data/sample_theses.json](data/sample_theses.json) содержит шесть карточек.
Это **JSON-массив** для программной индексации и CLI. HTTP принимает
**объект `{"cards": [...]}`**, а исходный JSONL — отдельный формат конвертера.

Подготовьте HTTP-файл и запрос поиска во втором терминале. Эти команды одинаковы
для bash/zsh и PowerShell; файлы записываются явно в UTF-8 без BOM. Каталог
`data/generated/` содержит воспроизводимые результаты и игнорируется Git.
Повторный запуск команд перезаписывает только указанные сгенерированные файлы:

```text
python -c "import json; from pathlib import Path; Path('data/generated').mkdir(parents=True, exist_ok=True); cards=json.loads(Path('data/sample_theses.json').read_text(encoding='utf-8')); Path('data/generated/sample_import.json').write_text(json.dumps({'cards': cards}, ensure_ascii=False, indent=2), encoding='utf-8')"
python -c "import json; from pathlib import Path; Path('data/generated/search.json').write_text(json.dumps(dict(query='Rasdaman', search_mode='bm25', top_k=10, debug=True)), encoding='utf-8')"
```

Загрузите корпус (**полная замена**, а не добавление):

```bash
curl --noproxy "*" -sS -i -X PUT http://127.0.0.1:8000/theses -H "Content-Type: application/json" --data-binary "@data/generated/sample_import.json"
```

```powershell
curl.exe --noproxy "*" -sS -i -X PUT http://127.0.0.1:8000/theses -H "Content-Type: application/json" --data-binary "@data/generated/sample_import.json"
```

Ожидается **200** и `{"status":"ok","documents_count":6,"search_mode":"bm25"}`.
Повторная проверка `/health` даст 200, `index_loaded=true`, `documents_count=6`.

Выполните поиск:

```bash
curl --noproxy "*" -sS -i -X POST http://127.0.0.1:8000/theses/search -H "Content-Type: application/json" --data-binary "@data/generated/search.json"
curl --noproxy "*" -sS -i http://127.0.0.1:8000/theses/hse-1162011207
```

```powershell
curl.exe --noproxy "*" -sS -i -X POST http://127.0.0.1:8000/theses/search -H "Content-Type: application/json" --data-binary "@data/generated/search.json"
curl.exe --noproxy "*" -sS -i http://127.0.0.1:8000/theses/hse-1162011207
```

Поиск вернёт **200**, `query="Rasdaman"`, `count=1` и работу
`hse-1162011207` («LLM для описания спутниковых данных»). В результате
`bm25_rank=1`, `score=1/61`, оба семантических поля равны `null`.
GET вернёт ту же карточку без score и диагностики.

Изменяйте `data/generated/search.json` редактором, сохраняя UTF-8:

```json
{"query":"Rasdaman","search_mode":"bm25","top_k":10,"debug":false}
```

При `debug=false` диагностических полей нет. Для запроса без общих токенов
будет 200 с `count=0` и `results=[]`. `top_k=0` даёт 422; `search_mode="hybrid"`
без подключённой Ollama — 503. Запрос неизвестного ID при загруженном корпусе — 404.
Остановите API и запустите той же командой: health и поиск снова дадут 200,
повторный импорт не нужен.

В PowerShell не используйте имя `curl` без `.exe`: в Windows PowerShell оно может
быть псевдонимом `Invoke-WebRequest` с другими аргументами. Передача JSON файлом
избегает различий экранирования кавычек и кодировки конвейера PowerShell 5.1/7.
Не используйте обычное перенаправление `>` в PowerShell 5.1 для создания JSON:
оно может записать UTF-16. `--data-binary "@путь с пробелами.json"` передаёт байты
файла без преобразования. `-i` показывает HTTP-статус; cURL без `--fail` не считает
HTTP 422/503 ошибкой процесса, поэтому смотрите сам статус.

Можно работать через [Swagger UI](http://127.0.0.1:8000/docs): **Try it out** →
вставьте содержимое подготовленного HTTP-файла → **Execute**. Не передавайте
путь к файлу в теле HTTP-запроса. Swagger использует внешние ресурсы оформления;
для полностью автономной проверки используйте cURL и `/openapi.json`.

## Подключение Ollama и BGE-M3

Установите Ollama по [официальной инструкции](https://docs.ollama.com/quickstart)
для своей ОС: [Windows](https://docs.ollama.com/windows),
[macOS](https://docs.ollama.com/macos), [Linux](https://docs.ollama.com/linux).
Проверьте доступность команды `ollama --version` в новом терминале. Приложение
не устанавливает Ollama, не запускает её сервер и не скачивает модель.

Запустите установленное приложение Ollama либо его системную службу. Если сервер
не запущен приложением/службой, откройте отдельный терминал и выполните:

```text
ollama serve
```

Команда занимает терминал; Ctrl+C останавливает именно этот сервер. Если порт
11434 уже занят работающей Ollama, второй экземпляр не нужен. Фоновое приложение
останавливается через его меню, служба — средствами ОС.

В другом терминале загрузите [BGE-M3](https://ollama.com/library/bge-m3)
и проверьте список локальных моделей:

```text
ollama pull bge-m3:latest
ollama list
```

Ожидается `bge-m3:latest` в списке. Загрузка требует сети и дискового пространства;
после неё кодирование выполняется локально. Команды управления описаны в
[справке CLI Ollama](https://docs.ollama.com/cli). Не меняйте модель во время
индексации или работы API.

Остановите FastAPI. В `.env` проекта установите:

```dotenv
OLLAMA_ENABLED=true
DATABASE_PATH=data/theses-bge-m3.sqlite3
```

Выберите новый файл, чтобы сохранить BM25-корпус из первого сценария. Удалите
переопределения этих переменных из окружения, если задавали их ранее. Запустите
API обычной командой с одним worker. При включённой интеграции startup обращается
к `/api/tags`; недоступность Ollama или отсутствие модели прерывает запуск.
При отсутствии полного индекса health вернёт 503, `search_mode="hybrid"`,
`embedding_model="bge-m3:latest"`. Существующая БД только с карточками также
ожидает повторного HTTP-импорта для построения векторов; автоматического кодирования
при старте нет, до импорта оба режима поиска недоступны.

Повторите PUT с `data/generated/sample_import.json` из предыдущего раздела.
Теперь импорт вычислит векторы и вернёт 200, `documents_count=6`,
`search_mode="hybrid"`. Импорт синхронный; дождитесь ответа. Измените запрос:

```json
{"query":"Rasdaman","search_mode":"hybrid","top_k":10,"debug":true}
```

Отправьте тем же POST. Ожидается 200 и семантическая диагностика. Порядок реальной
гибридной выдачи зависит от модели и не задаётся примером. BM25 на этом же индексе
по-прежнему доступен и не обращается к Ollama. При перезапуске векторы документов
читаются из SQLite, заново кодируется только каждый hybrid-запрос.

`OllamaEncoder` использует `bge-m3:latest`, 1024 компоненты и проверяет
L2-нормализацию. Digest модели из `/api/tags` сохраняется в метаданных индекса.
Префиксы текстам не добавляются. Для [`/api/embed`](https://docs.ollama.com/api/embed)
заданы `truncate=false` и `keep_alive="30m"`: превышение доступного контекста
вызывает ошибку, тексты не обрезаются. Размер реально доступного контекста зависит
от Ollama; приложение не считает токены и не разбивает текст на части.
`ollama stop bge-m3:latest` выгружает модель из памяти, сохраняя сервер и файлы;
следующий запрос снова загрузит её. Эти параметры Ollama не читаются из `.env`
проекта. HTTP-адаптер использует только loopback и не использует прокси окружения.

## CLI и предметный сценарий МИЭМ

### Полная индексация

Из корня проекта, при запущенной Ollama с загруженной BGE-M3 и **остановленном API**:

```text
python -m scripts.build_index --help
python -m scripts.build_index --input data/sample_theses.json --batch-size 32
```

CLI всегда строит гибридный индекс независимо от `OLLAMA_ENABLED`. Проверьте
`DATABASE_PATH` перед запуском: индекс в выбранной SQLite полностью заменяется.
`--input` принимает UTF-8 **массив карточек**, относительный путь разрешается
**от корня проекта**, абсолютный используется напрямую. `--batch-size` —
положительное целое, по умолчанию 32. Успех: код завершения 0 и
`Проиндексировано карточек: 6; обрезано текстов: 0`. Ошибка данных, Ollama или
хранилища даёт код 2 с диагностикой; прежний индекс сохраняется при сбое подготовки
или транзакции. После CLI запустите API с `OLLAMA_ENABLED=true` и той же БД.

### Что находится в data/

| Файл | Формат и назначение |
| --- | --- |
| [sample_theses.json](data/sample_theses.json) | Шесть карточек, JSON-массив; основной пример и тестовый корпус. Аннотации — пересказы, ключевые слова подобраны по содержанию; URL ведут к оригиналам ВШЭ |
| [works_miem_2026_ver0-0-3.jsonl](data/works_miem_2026_ver0-0-3.jsonl) | Исходная предметная выгрузка работ МИЭМ, одна запись на строку; напрямую API/индексатором не принимается |
| [works_miem_2026_import.json](data/works_miem_2026_import.json) | Подготовленный объект `{"cards": [...]}` для HTTP-импорта |
| [supervisor_profiles_miem_ver0-0-3.jsonl](data/supervisor_profiles_miem_ver0-0-3.jsonl) | Исходные профили руководителей; текущий поиск и конвертер их не используют |
| `generated/` | Локальные производные JSON из инструкций; не исходные данные, игнорируются Git |
| `*.sqlite3` | Локальная БД пользователя, создаётся при импорте; игнорируется Git |

Выгрузка МИЭМ не нужна для основного запуска. Чтобы подготовить новый HTTP-файл,
не изменяя поставленный корпус, из корня проекта выполните:

```text
python -m scripts.prepare_miem_import --help
python -c "from pathlib import Path; Path('data/generated').mkdir(parents=True, exist_ok=True)"
python -m scripts.prepare_miem_import --input data/works_miem_2026_ver0-0-3.jsonl --output data/generated/miem_import.json
```

У конвертера **оба относительных пути отсчитываются от текущего рабочего каталога**.
Родительский каталог результата должен существовать. Выходной файл перезаписывается;
одинаковые входной и выходной пути запрещены. Код 0 означает успех, 2 — ошибку.

Конвертер проверяет карточки перед записью. ID — `hse-<номер страницы>` из ссылки
`www.hse.ru/edu/vkr/<номер>`. Поля `title`, `annotation`, `source_url`, `author_raw`,
`defense_year` преобразуются в название, описание, URL, автора и год. Явный список
ключевых слов извлекается из аннотации, оставшийся текст сохраняется; нормализуются
пробелы и мягкие переносы. Это правила для данной выгрузки, не универсальный парсер:
проверяйте результат при изменении формата аннотаций. Ключевые слова не генерируются.
Другие метаданные, включая руководителей и программу, остаются только в JSONL.

Для HTTP отправьте `data/generated/miem_import.json` тем же PUT, заменив имя файла
в предыдущем примере. Также можно отправить готовый `data/works_miem_2026_import.json`.
Ожидается 200 с количеством переданных карточек; весь прежний корпус будет заменён.

Если нужен **CLI**, сначала извлеките массив из созданного HTTP-объекта:

```text
python -c "import json; from pathlib import Path; payload=json.loads(Path('data/generated/miem_import.json').read_text(encoding='utf-8')); Path('data/generated/miem_cards.json').write_text(json.dumps(payload['cards'], ensure_ascii=False, indent=2), encoding='utf-8')"
python -m scripts.build_index --input data/generated/miem_cards.json --batch-size 32
```

Последняя команда требует работающей Ollama, модели и остановленного API,
как описано выше. Перед ней проверьте целевую БД.

### Запуск из другого рабочего каталога

Самый простой вариант — перейти в корень проекта. Для API можно использовать
абсолютный путь к Python окружения и `--app-dir "путь к корню проекта"` с `main:app`;
`DATABASE_PATH` всё равно останется относительно корня проекта.
Для `python -m scripts...` корень должен быть доступен для импорта: либо перейдите
в него, либо добавьте его абсолютный путь в `PYTHONPATH` через `export` (bash/zsh)
или `$env:PYTHONPATH` (PowerShell). Прямой запуск `python scripts/build_index.py`
не является документированным способом запуска. Программные вызовы
`SQLiteStorage(path)` и `read_corpus(path)` разрешают относительные пути от CWD;
правило от корня относится к настройке БД и аргументу CLI `build_index`.

## Тесты

Из корня проекта, с Python выбранного окружения:

```text
python -m pip install -r requirements-dev.txt
python -m pip check
python -m pytest -q
```

Ожидаются успешно пройденные тесты; POSIX-проверка имени файла с `?` пропускается
на Windows. Обычные тесты используют временные SQLite и отдельный корень настроек,
очищают поддерживаемые переменные окружения и не читают личную `.env`.
Неподменённые сетевые подключения запрещены. HTTP-контракты проверяются через
TestClient, вычисления hybrid — фиксированными векторами, транспорт Ollama — подменой.
Это не проверка настоящих весов, качества релевантности или другой ОС.

С закреплёнными версиями Starlette может вывести предупреждение об устаревании
тестового транспорта `httpx`. Оно не означает сбой тестов; переход на другой
транспорт не нужен для воспроизведения текущего окружения.

Проверяются валидация, ранжирование, порядок ID и векторов, транзакционный откат,
запуск без БД, HTTP-импорт, перезапуск, конкурентная публикация снимков, пути
с пробелами/кириллицей и различия CWD. Реальный HTTP-сценарий вручную воспроизводится
разделами «Запуск BM25» и «Импорт и поиск». Для проверки настоящей Ollama повторите
раздел её подключения; сеть и модель не являются условием unit-тестов.

## Контракты, ограничения и устранение ошибок

| Метод | Успех и ожидаемые ошибки |
| --- | --- |
| `PUT /theses` | 200 — весь корпус сохранён и опубликован; 422 — неверное тело; 503 — ожидаемая недоступность хранилища/энкодера |
| `POST /theses/search` | 200 — результаты, в том числе пустые; 422 — неверный запрос; 503 — нет корпуса или нужного энкодера |
| `GET /theses/{thesis_id}` | 200 — карточка; 404 — неизвестный ID при загруженном корпусе; 503 — поиск не готов |
| `GET /health` | 200 — снимок готов; 503 — ожидается импорт; `search_mode` здесь обозначает тип индекса, а не выбор режима запроса |

Карточка требует непустые строки `id`, `title`, `abstract` и HTTP(S)-ссылку `url`.
Крайние пробелы удаляются, ID уникальны после нормализации и не содержат `/`.
`keywords` — список строк (по умолчанию `[]`), `author` — строка или `null`,
`year` — целое или `null`. Неизвестные поля и неправильные типы отклоняются.
Поисковый `query` после strip содержит букву или цифру и имеет 1–4000 символов;
`top_k` — целое 1–100 (по умолчанию 10), `debug` — boolean (по умолчанию false).

Импорт готовит новый поиск до записи, одной SQLite-транзакцией сохраняет корпус,
затем публикует снимок. Ошибка подготовки или записи оставляет прежние данные
и поиск. При BM25-импорте прежние векторы и метаданные удаляются; при включённой
Ollama документы кодируются батчами по 32. Импорты сериализованы; старый запрос
может закончиться на старом целом снимке. Hybrid-запросы и импорт разделяют одну
блокировку энкодера. Внешние изменения БД автоматически не отслеживаются:
после CLI требуется перезапуск, параллельные внешние индексаторы не поддерживаются.

SQLite хранит векторы как float32 little-endian BLOB без pickle и связывает их
с ID. Проверяются набор ID, размерность, конечность, L2-нормы с допуском float32,
модельный digest и версия подготовки текста. Равная размерность разных моделей
не означает совместимость. Смена модели/digest требует полной переиндексации
и перезапуска. При переносе полного индекса установите ту же модель либо
перестройте индекс из карточек на целевой машине.

BM25 учитывает только название, ключевые слова и описание: нижний регистр,
`ё` → `е`, буквенно-цифровые Unicode-токены. Лемматизации нет. Автор, год, URL
и ID не участвуют в ранжировании. Общие токены являются условием BM25-кандидата,
даже когда его сырой score нулевой или отрицательный. Семантический поиск — точное
скалярное произведение L2-векторов. Итоговая оценка RRF — сумма
`1 / (60 + rank)` по присутствующим каналам; позиции начинаются с 1.
В каждом канале до `min(100, размер корпуса)` кандидатов. При равенстве оценок
используется строковый ID по возрастанию; округления перед сортировкой нет.
Score не является вероятностью. Порога релевантности нет: hybrid может вернуть
ближайшие работы даже для темы вне корпуса. Качество требует отдельной оценки.

Корпус и индексы находятся в памяти; ориентир MVP — до примерно 10 000 коротких
карточек и небольшой поток запросов, не гарантированный предел производительности.
Нет авторизации, UI, генерации ответов, поиска по PDF/DOCX, чанкинга, CRUD отдельных
карточек, multipart, скачивания URL и фоновой синхронизации. Не открывайте этот
локальный API с полной заменой корпуса в недоверенную сеть.

| Симптом | Что проверить |
| --- | --- |
| `No module named ...` | Корень проекта, интерпретатор `.venv`, установку requirements; запуск через `python -m` |
| Не устанавливается закреплённая зависимость | Версию Python, доступ к индексу пакетов и wheels для своей платформы; не подменяйте версии вслепую |
| Изменения `.env` не действуют | Перезапуск и приоритет переменных окружения |
| 503 до импорта | Загрузите непустой объект `{"cards": [...]}`; не создавайте пустую БД вручную |
| 422 при импорте/поиске | Поле `detail`, формат массива/объекта, уникальность ID, типы и кодировку UTF-8 |
| Startup падает на SQLite | Путь, права, существующий пустой файл, схему и целостность БД; приложение не ремонтирует её перезаписью |
| Несовместим гибридный индекс | Остановите API, подготовьте исходный JSON-массив и выполните CLI на выбранной БД; смена digest требует новых векторов |
| БД повреждена | Сохраните старый файл, выберите новый `DATABASE_PATH` и импортируйте исходный корпус; CLI не исправляет неверную схему |
| Ollama не найдена/не отвечает | `ollama --version`, запущенный локальный сервер, порт в `OLLAMA_BASE_URL`, наличие `bge-m3:latest` в `ollama list` |
| 503 при hybrid или импорте | Логи приложения, доступность Ollama, длину текста и таймаут; автоматического fallback нет |
| Длинный текст отклонён | Ограничение контекста Ollama при `truncate=false`; подготовьте более короткую карточку, автоматического чанкинга нет |
| Health 200, но hybrid возвращает 503 | Health не проверяет inference; восстановите Ollama. BM25 на загруженном снимке продолжает работать |
| BM25 ничего не находит | Совпадение токенов, включая форму слова; попробуйте точное слово из корпуса |

В логах приложения при INFO видны начало/итог импорта и запросов Ollama,
количество документов, длительность и безопасная категория ошибки. `status=ok`
батча ещё не означает сохранение корпуса; итог импорта `status=saved` означает
запись и публикацию. Тексты, векторы и тела ответов в этих логах отсутствуют.
