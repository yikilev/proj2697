# Поиск выпускных квалификационных работ

FastAPI-бэкенд для поиска карточек ВКР. Рабочий режим `bm25` использует настоящую
файловую SQLite через стандартный `sqlite3`, без эмбеддера и векторов. Сервер
запускается без заранее созданной БД; корпус загружается через `PUT /theses`,
и поиск обновляется без перезапуска. После перезапуска карточки читаются из SQLite.

Алгоритмы семантического поиска и объединения рейтингов реализованы, но настоящий
эмбеддер пока не подключён. Обычный запуск `SEARCH_MODE=hybrid` завершается ошибкой,
автоматического перехода на BM25 нет. Тесты с фиксированными fake-векторами проверяют
вычисления и контракты, а не работу реальной модели или качество гибридного поиска.

## Быстрый запуск

Команды для bash/zsh. Используйте Python 3.12: текущий проект и зависимости проверены
на Python 3.12.10. Заявленная ранее целевая версия 3.11 пока не проверена.

В первом терминале:

```bash
cd /Users/artem/proj/proj_2697/proj2697
if [ ! -d .venv ]; then python3.12 -m venv .venv; fi
source .venv/bin/activate
python -m pip install -r requirements.txt
export SEARCH_MODE=bm25
export DATABASE_PATH=data/theses.sqlite3
python -m uvicorn main:app --host 127.0.0.1 --port 8000 --workers 1
```

Существующее `.venv` используется повторно. Установка зависимостей не скачивает
веса модели. Поддерживается **один worker**: активный поисковый снимок и блокировка
импортов принадлежат одному процессу.

Заранее создавать файл SQLite или его таблицы не нужно. Отсутствующая БД и её
родительские каталоги создаются при первом успешном импорте. Если по указанному
пути уже сохранён корпус, он загрузится при старте и health сразу вернёт 200.
Для проверки состояния до первого импорта укажите другой, ещё не существующий
файл в `DATABASE_PATH`; не создавайте пустой файл вручную.

Все следующие команды `curl` выполняются **во втором терминале, пока сервер работает**.
Ключ `-i` показывает HTTP-статус вместе с телом ответа.

### Health до первого импорта

```bash
curl -sS -i http://127.0.0.1:8000/health
```

Для отсутствующей БД ожидается **503**:

```json
{"status":"not_ready","index_loaded":false,"documents_count":0,"search_mode":"bm25","embedding_model":null}
```

Сервер при этом работает: доступны `/docs`, `/openapi.json` и импорт.
Поиск и получение карточки до первого импорта возвращают 503 с сообщением
`Корпус не загружен. Загрузите карточки через PUT /theses` в поле `detail`.

### Импорт небольшого корпуса

Это полная замена корпуса, включая ранее сохранённые карточки:

```bash
curl -sS -i -X PUT http://127.0.0.1:8000/theses \
  -H 'Content-Type: application/json' \
  --data-binary @- <<'JSON'
{
  "cards": [
    {
      "id": "thesis-001",
      "title": "Гибридный поиск научных работ",
      "abstract": "Поиск по описаниям с использованием BM25 и эмбеддингов.",
      "keywords": ["BM25", "поиск"],
      "author": "Иван Иванов",
      "year": 2025,
      "url": "https://example.org/theses/001"
    },
    {
      "id": "thesis-002",
      "title": "Управление мобильным роботом",
      "abstract": "Навигация робота по карте помещения и обход препятствий.",
      "keywords": ["робот", "навигация"],
      "author": "Анна Петрова",
      "year": 2024,
      "url": "https://example.org/theses/002"
    }
  ]
}
JSON
```

Ожидается **200**:

```json
{"status":"ok","documents_count":2,"search_mode":"bm25"}
```

### Health после импорта

```bash
curl -sS -i http://127.0.0.1:8000/health
```

Ожидается **200**:

```json
{"status":"ok","index_loaded":true,"documents_count":2,"search_mode":"bm25","embedding_model":null}
```

### Поиск и диагностика

```bash
curl -sS -i -X POST http://127.0.0.1:8000/theses/search \
  -H 'Content-Type: application/json' \
  --data-binary '{"query":"поиск","top_k":10,"debug":false}'
```

Ожидается **200**, `count=1`, карточка `thesis-001` в `results`.
Поля карточки и `score` находятся непосредственно в элементе `results`.
Диагностические поля при `debug=false` отсутствуют.

```bash
curl -sS -i -X POST http://127.0.0.1:8000/theses/search \
  -H 'Content-Type: application/json' \
  --data-binary '{"query":"поиск","top_k":10,"debug":true}'
```

Ожидается **200** с той же выдачей и `score`. Добавляются `bm25_score`,
`bm25_rank`, `semantic_score`, `semantic_rank`. В BM25 оба семантических поля
равны `null`; у единственного результата `bm25_rank=1`.

### Получение карточки

```bash
curl -sS -i http://127.0.0.1:8000/theses/thesis-001
```

Ожидается **200**, исходная карточка без `score` и диагностики.
Неизвестный ID при загруженном корпусе возвращает **404**.

### Ошибочный запрос

После импорта выполните запрос с недопустимым `top_k=0`:

```bash
curl -sS -i -X POST http://127.0.0.1:8000/theses/search \
  -H 'Content-Type: application/json' \
  --data-binary '{"query":"поиск","top_k":0,"debug":false}'
```

Ожидается **422**, поле `detail` содержит список ошибок валидации.

### Загрузка data/sample_theses.json через HTTP

Второй терминал: стандартный Python читает локальный UTF-8 JSON-массив,
оборачивает его в объект с полем `cards` и передаёт JSON в stdin `curl`.
Отдельный скрипт, CLI-индексация и `jq` не нужны.

```bash
cd /Users/artem/proj/proj_2697/proj2697
source .venv/bin/activate
python - <<'PY' | curl -sS -i -X PUT http://127.0.0.1:8000/theses -H 'Content-Type: application/json' --data-binary @-
import json
import sys
from pathlib import Path

cards = json.loads(Path("data/sample_theses.json").read_text(encoding="utf-8"))
json.dump({"cards": cards}, sys.stdout, ensure_ascii=False)
PY
```

Ожидается **200**, `documents_count=6`. Эти шесть карточек полностью заменяют
корпус из предыдущего примера: `thesis-001` и `thesis-002` больше не доступны.
В наборе — карточки ВКР НИУ ВШЭ со ссылками на оригиналы; описания являются
краткими пересказами, ключевые слова подобраны по содержанию.

```bash
curl -sS -i -X POST http://127.0.0.1:8000/theses/search \
  -H 'Content-Type: application/json' \
  --data-binary '{"query":"влияние","top_k":10,"debug":false}'
```

Для текущего sample-корпуса ожидается **200**, `count=4`.

### Swagger UI

Откройте [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).
В `PUT /theses` нажмите **Try it out**, замените тело запроса на JSON небольшого

передавать не нужно. Импорт через Swagger тоже полностью заменяет корпус.

## Контракты и ограничения

| Метод и путь | Контракт |
| --- | --- |
| `PUT /theses` | JSON-объект с непустым массивом `cards`; полная замена корпуса в BM25; успех — 200 |
| `POST /theses/search` | JSON с `query`, `top_k`, `debug`; ответ содержит `query`, `count`, `results` |
| `GET /theses/{thesis_id}` | Карточка без score; 404 для неизвестного ID при готовом поиске, иначе 503 |
| `GET /health` | 200 при готовом поиске, 503 до первого импорта; фактический режим и размер корпуса |

У карточки обязательны непустые строки `id`, `title`, `abstract` и HTTP(S)-ссылка
`url`. Пробелы по краям строк удаляются, ID не может содержать `/`.
`keywords` — список строк (по умолчанию пустой), `author` — строка или `null`,
`year` — целое число или `null`. Неизвестные поля и неверные типы отклоняются.

`query` после удаления крайних пробелов должен содержать букву или цифру и иметь
длину 1–4000 символов. `top_k` — целое число 1–100, по умолчанию 10;
`debug` — JSON boolean, по умолчанию `false`. Неизвестные поля дают 422.

- Пустой корпус, повторяющиеся ID после нормализации, невалидные карточки и
  неизвестные поля импорта возвращают **422 до изменения данных**.
- Импорт BM25 транзакционно заменяет все карточки и удаляет старые векторы и
  модельные метаданные. Это не добавление к существующему корпусу.
- Сначала строится новый BM25-сервис в памяти, затем сохраняется SQLite и
  публикуется новый поисковый снимок. Успешный ответ означает, что новый поиск
  уже доступен. Ошибка подготовки или записи сохраняет предыдущие данные и поиск.
  Ожидаемая недоступность хранилища при импорте возвращает 503 без SQL и серверных путей.
- Импорты сериализуются блокировкой экземпляра приложения. Начатый ранее запрос
  может завершиться на старом целом снимке; данные двух снимков не смешиваются.
- После перезапуска сохранённый корпус загружается из SQLite. Внешние изменения
  файла БД автоматически не отслеживаются.
- Отсутствующий файл БД допустим в BM25. Повреждённая БД, пустой существующий файл,
  неверная схема, пустой сохранённый корпус и ошибки доступа прерывают startup;
  они не считаются отсутствующим корпусом и не исправляются перезаписью.
- `hybrid` без реального эмбеддера не запускается. Существующий гибридный сервис
  допускает явное внедрение зависимостей через `create_app(dependency_factory=...)`;
  фабрика имеет приоритет над `SEARCH_MODE`. Импорт с валидным телом в фактическом
  режиме `hybrid` возвращает **409**, не меняя БД и поиск. После программной полной
  переиндексации hybrid требуется перезапуск.

BM25 ищет совпадения токенов в названии, ключевых словах и описании. Токенизация
приводит текст к нижнему регистру, заменяет `ё` на `е` и выделяет буквенно-цифровые
Unicode-токены. Лемматизации и синонимов нет: разные формы слова могут не совпасть.
Автор, год, URL и ID не участвуют в ранжировании. Без общих токенов ответ —
`count=0`, `results=[]`; нулевой или отрицательный BM25 score не исключает совпадение.

Итоговый `score` — оценка Reciprocal Rank Fusion, **не вероятность и не процент
соответствия**. В BM25 это `1 / (60 + bm25_rank)`; в hybrid добавляется такой же
вклад семантической позиции. Позиции начинаются с 1. Каждый канал получает до
`min(100, размер корпуса)` кандидатов. Результаты сортируются по убыванию score,
при равенстве — по строковому ID по возрастанию; возвращается не более `top_k`.
Порог релевантности не задан. Семантический канал при подключении модели выдаёт
ближайшие работы, что само по себе не гарантирует тематическую близость.

Нет CRUD отдельных карточек, multipart, скачивания внешних URL, обработки PDF/DOCX,
поиска по полным текстам, пагинации и фоновой синхронизации.

## Настройки

Настройки читаются из окружения процесса при startup:

| Переменная | По умолчанию | Допустимые значения и поведение |
| --- | --- | --- |
| `SEARCH_MODE` | `bm25` | Только `bm25` или `hybrid`, регистр важен; hybrid требует подключённого эмбеддера |
| `DATABASE_PATH` | `data/theses.sqlite3` | Путь к файлу SQLite; относительный — от корня проекта с `main.py`, независимо от рабочего каталога |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`, `NOTSET`; регистр не важен |

`.env` **автоматически не читается**: создание этого файла не меняет настройки.
Используйте `export`, как в быстром запуске, или переменные перед командой процесса.
Настроек модели, устройства, размера батча и лимита кандидатов в окружении нет.
`LOG_LEVEL` задаёт уровень корневого logger приложения; собственные логи Uvicorn
управляются его `--log-level`. Приложение не логирует тексты запросов, корпус и матрицы.

Относительный путь `data/sample_theses.json` в Python-команде импорта разрешается
от рабочего каталога второго терминала, поэтому перед ней указан `cd`.
При прямом программном использовании `SQLiteStorage(path)` относительный путь
также отсчитывается от рабочего каталога; правило от корня проекта относится
к настройке `DATABASE_PATH`. При запуске Uvicorn из другого каталога необходимо
указать `--app-dir /Users/artem/proj/proj_2697/proj2697`, чтобы найти `main`;
это не изменит разрешение `DATABASE_PATH`.

## Внутренние интерфейсы

`services.search.BM25SearchService` загружает карточки SQLite один раз;
`from_cards(cards)` строит снимок из валидированных карточек для HTTP-импорта.
`services.search.SearchService` загружает полный снимок, строит BM25 и точный
семантический индекс через NumPy и объединяет рейтинги RRF. Оба сервиса предоставляют
`search`, `get_thesis`, `health`. Запросы используют готовый снимок в памяти;
документы при поиске повторно не кодируются и не читаются из БД.

`services.indexing.build_index` сохраняет программный интерфейс полной индексации:
UTF-8 JSON-массив → валидация → батчевое кодирование → проверка векторов →
одна транзакционная замена снимка. `Encoder` в `external/embedder.py` — контракт,
а не подключённая модель. Подготовка префиксов E5 и реальный учёт обрезки требуют
адаптера. Существующий вспомогательный CLI не требуется для HTTP-сценария.

`SQLiteStorage.replace_cards` сохраняет только карточки; `replace_snapshot` —
карточки, векторы и метаданные. Векторы связаны с ID и хранятся как float32 BLOB
little-endian без pickle. Полный снимок проверяется на соответствие ID, размерности,
конечность и L2-нормализацию векторов, совместимость модели и версии подготовки
текста. BM25 не читает векторы и модельные метаданные. Чтение SQLite выполняется
в одной транзакции; синхронные операции API и подготовка сервиса — в пуле потоков.

## Проверки

Из корня проекта:

```bash
cd /Users/artem/proj/proj_2697/proj2697
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

`requirements-dev.txt` включает прикладные зависимости, pytest и httpx.
Тесты покрывают схемы и HTTP-контракт, BM25, RRF, семантические вычисления с
фиксированными векторами, индексацию и транзакционное SQLite-хранилище.
`tests/test_http_import.py` и `tests/test_startup.py` проверяют запуск без БД,
импорт, немедленную замену поиска, ошибки без потери прежних данных и перезапуск.
Конкурентные импорты и запрос на старом снимке проверяются управляемыми событиями,
без случайных задержек. Для проверок хранения используется настоящая временная SQLite.

Фактическая проверка 12 ноября 2026 года: **485 passed in 1.49s**. Отдельно проверен
настоящий Uvicorn через HTTP с одним worker и временной SQLite: до импорта `/docs`
возвращает 200, health/поиск/карточка — 503; импорт sample — 200 и 6 карточек;
поиск «влияние» — 4 результата; debug, top_k, 404 и 422 соответствуют контракту.
Замена корпуса доступна без перезапуска, невалидный импорт сохраняет предыдущие
данные, после перезапуска корпус и поиск восстанавливаются из SQLite.

При обновлении документации отдельно выполнены все девять curl-примеров из этого
README: статусы и количество результатов совпали с указанными. В Swagger UI
проверены редактирование JSON-тел, импорт двух карточек и поиск с `debug=true`;
оба запроса вернули 200. Полный набор тестов повторно ради правок текста не запускался.

Проверенное окружение: Python 3.12.10, Pydantic 2.14.3, pytest 9.2.0,
NumPy 2.4.6, rank-bm25 0.2.2, FastAPI 0.162.4, Starlette 1.10.0, httpx 0.28.1.
Реальный эмбеддер не подключён; интеграция с настоящими весами и качество
гибридного поиска пока не проверены.
